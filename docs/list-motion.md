# 消息列表里的动效

聊天的消息列表（电脑和手机网页共用 `web/src/Chat.tsx` 的行）跟随到底：停在最底下时，新东西来了面板会跟过去（`virtual/list.tsx`）。列表里什么东西一变，就会和这个滚动互相影响。下面的规则就是为此定的，改动效之前先读。

## 一个时钟（`virtual/pace.ts`）

列表里所有让东西在屏幕上移动的变化，由一个调度器按同一条规律、在同一个帧循环里画出来，不各走各的时钟：

- 列表本身的变化一律立刻到位：面板直接滚到锚点要的位置（`model.ts` 不再分步滑动），行直接排在新位置。
- 调度器在每次变化后看每一行在屏幕上被挪了多少（读者自己滚动的不算，`scrolledBy`），把这一行先画回原处（CSS `translate`，和行自己动画用的 `transform` 分开），再收回到 0。
- 规律是 `@stillfail/ui` `motion.ts` 的 `PACE_*`：从静止放开的临界阻尼弹簧，320ms 到位（剩 2%）；距离长就走得久，任何一行最快不超过 `PACE_MOST`（1.2px/ms）。起步时速度为 0，不会一帧里从静止跳到全速。
- 同一帧里被挪动的所有行共用一次运动（`Wave`：同一速率、同一起点），一起走；先后发生的几次变化各自从当前位置接着走、相加，速度不突变。
- 新做出来的行（刚来的消息、活动行、为画出偏移的内容补做的行）跟它前面那一行一样偏移，跟着一起进来。面板跳得比做出来的行还远时（从很上面回到底部），新的行从面板边缘外滑进来，最多一屏高。
- 不画过程的：读者自己的滚动、列表刚打开、跳到某条消息（`goto`）、面板尺寸变化、按性质就该立刻到位的（补拉的历史）。
- 减少动画时同一个时钟走得快（`paceRate` 为无穷大），一切立刻到位。

## 两类动效

**只改透明度和位置的**：不碰行高，滚动也不受影响。

- 进场统一用 `motion.ts` 的 `ENTER` / `ENTER_FROM`：从下方 6px 处淡入，220ms 缓出。新消息的 `[data-enter]`、决策收起后出现的那行字、「忽略」「留着/归档」出现时，都是这一种。
- 离场统一用 `LEAVE` / `LEAVE_TO`：在原处放一个副本，缩小到 0.9 并淡出，200ms。和侧栏的行离开一样（`listMotion.ts`）。

**会改变行高的**：决策选项收起成一行字，「忽略」「留着/归档」出现或消失。都走 `settling.tsx`，要求如下：

1. 不在中途排出临时尺寸。先把框按当前高度钉住，在钉住的框里排新内容，再从内容算出终点。如果框真的缩了一下，哪怕只是为了量尺寸，停在底部的面板也会被浏览器拉上去一下。
2. grid 的间距跟着一起收。grid 的行高最小是 0，单靠负 margin 抵不掉上面的间距，所以由前一个元素在收起过程中把这段间距让出来，展开时再还回去。
3. 一开始就告诉列表这一行最后有多高。`rowHeights.ts` 在行上写 `data-settles-to`，列表据此算出最终滚到哪里（`model.ts` 的 `coming`），然后一次滑过去，不再每帧追着当前高度跑。
4. 框的高度挂在列表的时钟上（`pace.ts` 的 `paceWith`）：和它带动的行属于同一次运动，同一帧起步、同一速率，上面和下面的东西各自只朝一个方向动、彼此严丝合缝。框下面的行跟着框走，不再被调度器另算一次（`model.ts` 的 `closedBefore`）。只能用固定时长 CSS 动画的地方（展开）用 `PACE_MS` / `PACE_EASE`。

### 例外

- agent 的消息从头像里吐出来（`useEmissions`）：整行高度一次到位，内容靠合成器从头像角展开，再配合头像的飞行。这样设计是为了长消息展开时不用每帧重新排版。等待中的消息不占位置，也不显示；列表事先就知道它不占位置（`Item.exact`），不按估计的高度先挪一下下面的东西。
- 活动行的出现（`Activity`）：位置一次到位，由列表的时钟带着它和上面的东西一起上来，自己只淡入、从头像长出来。消失时用 Motion 动 `grid-template-rows`，列表会为离开的临时行留出空间（`model.ts` 的 `held`），所以不带动别的行。刚发出的消息还在飞的时候，新出现的活动行先收着，等消息落下（`madeChat.ts` 的 `whenLanded`）再出现。
- 头像飞行、发送飞入读的是行画出来的位置（含调度器的偏移：`Pace.drawnOff`、`getBoundingClientRect`），落在列表正在走的地方。

## 检查

`test/browser/list-settle.mjs` 在官网 demo 的聊天里（假 core，用真页面）分别在宽屏和手机尺寸下各跑一遍，场景有：一个完整回合、回复和结束同时到、发消息、发消息后 agent 立刻开始干活、agent 回消息、比屏幕还高的回复、回复决策、点选项、忽略、留着/归档的出现和消失、活动行的出现和消失、agent 消息从头像吐出。每一帧都在列表把滚动摆正之后、绘制之前取样，下面任何一条出现就算失败：

- 有一行在三帧之内先往一个方向移、再往回移，两次都超过 2px；
- 自己的消息还在从输入框飞向列表时，新出现的活动行已经显示出来（应该等消息落下后，出现在它下面）；
- 结束时面板没有停在底部（比屏幕还高的回复除外，它是从顶部开始读的）；
- 有一行在屏幕上移动得比列表的规律允许的快（1.2px/ms，两件事叠加时留 30% 余量），或速度变化得比它允许的急（0.06px/ms²，留 60%）。速度按帧的时间（`document.timeline`）算，同一帧里取到的几次只留最后一次。

场景里有一个完整回合（`turn`：发消息、agent 马上开始干活、回复和结束同时到）和「回复和结束同时到」（`finish`），专门看几件事叠在一起时的速度。

它不检查时长：掉帧只会让样本变少，不会改变东西移动的方向。瞬移（一帧里走了 24px 以上、速度是前后帧三倍以上）只打印出来不判失败：慢机器上一帧拖长，正常滑动的一步也会变大；加 `JUMPS=1` 才按失败算，本机查问题时用。

完整检查（`scripts/check.sh full`）里，它跟在 stories.mjs 后面，在同一步依次跑。本机跑的方法：

```
PLAYWRIGHT_MODULE=<playwright-core 的 index.mjs> PLAYWRIGHT_CHANNEL=chrome node test/browser/list-settle.mjs
```

加 `ONLY=<场景>` 只跑一个场景，加 `SHOTS=<目录>` 会把每个场景的逐帧数据存下来。
