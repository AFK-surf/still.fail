# 消息列表里的动效

聊天的消息列表（电脑和手机网页共用 `web/src/Chat.tsx` 的行）跟随到底：停在最底下时，新东西来了面板会滑过去（`virtual/list.tsx`）。列表里什么东西一变，就会和这个滚动互相影响。下面的规则就是为此定的，改动效之前先读。

## 会改变列表高度的动效排队播放（`listQueue.ts`）

会改变消息列表高度的动效一次只播一个，按发生的顺序排队；前一个自己的动画播完、并且列表滚到位以后，下一个才开始。不改高度的（淡入淡出、头像的圈、文字切换）照常同时播。

- 进队列的：自己发的消息飞进来（发出时就排上，轮到前文字留在输入框里，行不占位置）、别人的/直接进来的消息（`[data-enter]`）、agent 消息从头像吐出来（一个 agent 连着吐的几条算一段）、活动行出现、决策选项收起、`Settles` 的出现和收起。
- 排着队的行加 `data-queued`：不显示、不占位置，列表把它当成「等着吐出来的消息」一样算高度（`virtual/list.tsx`）。
- 每一项最多占 3 秒，自己没说结束也让给下一个。
- 不进队列：图片加载完撑高这类不是动画的变化；活动行消失（列表给它留着位置，不带动别的行）。

## 两类动效

**只改透明度和位置的**：不碰行高，滚动也不受影响。

- 进场统一用 `motion.ts` 的 `ENTER` / `ENTER_FROM`：从下方 6px 处淡入，220ms 缓出。新消息的 `[data-enter]`、决策收起后出现的那行字、「忽略」「留着/归档」出现时，都是这一种。
- 离场统一用 `LEAVE` / `LEAVE_TO`：在原处放一个副本，缩小到 0.9 并淡出，200ms。和侧栏的行离开一样（`listMotion.ts`）。

**会改变行高的**：决策选项收起成一行字，「忽略」「留着/归档」出现或消失。都走 `settling.tsx`，要求如下：

1. 不在中途排出临时尺寸。先把框按当前高度钉住，在钉住的框里排新内容，再从内容算出终点。如果框真的缩了一下，哪怕只是为了量尺寸，停在底部的面板也会被浏览器拉上去一下。
2. grid 的间距跟着一起收。grid 的行高最小是 0，单靠负 margin 抵不掉上面的间距，所以由前一个元素在收起过程中把这段间距让出来，展开时再还回去。
3. 一开始就告诉列表这一行最后有多高。`rowHeights.ts` 在行上写 `data-settles-to`，列表据此算出最终滚到哪里（`model.ts` 的 `coming`），然后一次滑过去，不再每帧追着当前高度跑。
4. 框的高度和面板的滚动用同一规律、从同一帧开始走：`motion.ts` 的 `GLIDE_TAU`（每帧走剩下距离的一部分，约 250ms 走完 90%），`GLIDE_MS` / `GLIDE_EASE` 是同一规律写成固定时长的动画。这样上面和下面的东西各自只朝一个方向动。活动行在上面的东西变化时会保持在原位，它的滑动也用同一规律（`glider`）。

### 例外

- agent 的消息从头像里吐出来（`useEmissions`）：整行高度一次到位，内容靠合成器从头像角展开，再配合头像的飞行。这样设计是为了长消息展开时不用每帧重新排版。等待中的消息不占位置，也不显示；列表事先就知道它不占位置（`Item.exact`），不按估计的高度先挪一下下面的东西。
- 活动行的出现和消失（`Activity`）：用 Motion 动 `grid-template-rows`。列表会为离开的临时行留出空间（`model.ts` 的 `held`）。新出现的活动行在队列里排在刚发出的消息后面，等它落下、列表到位再出现。

## 检查

`test/browser/list-settle.mjs` 在官网 demo 的聊天里（假 core，用真页面）分别在宽屏和手机尺寸下各跑一遍，场景有：发消息、发消息后 agent 立刻开始干活、agent 回消息、比屏幕还高的回复、回复决策、点选项、忽略、留着/归档的出现和消失、活动行的出现和消失、agent 消息从头像吐出。每一帧都在列表把滚动摆正之后、绘制之前取样，下面任何一条出现就算失败：

- 有一行在三帧之内先往一个方向移、再往回移，两次都超过 2px；
- 自己的消息还在从输入框飞向列表时，新出现的活动行已经显示出来（应该等消息落下后，出现在它下面）；
- 结束时面板没有停在底部（比屏幕还高的回复除外，它是从顶部开始读的）。

它不检查时长：掉帧只会让样本变少，不会改变东西移动的方向。瞬移（一帧里走了 24px 以上、速度是前后帧三倍以上）只打印出来不判失败：慢机器上一帧拖长，正常滑动的一步也会变大；加 `JUMPS=1` 才按失败算，本机查问题时用。

完整检查（`scripts/check.sh full`）里，它跟在 stories.mjs 后面，在同一步依次跑。本机跑的方法：

```
PLAYWRIGHT_MODULE=<playwright-core 的 index.mjs> PLAYWRIGHT_CHANNEL=chrome node test/browser/list-settle.mjs
```

加 `ONLY=<场景>` 只跑一个场景，加 `SHOTS=<目录>` 会把每个场景的逐帧数据存下来。
